## 1. Цель работы

Разработать профилировщик, поддерживающий вложенные замеры выполнения функций, вычисление общего и собственного времени, а также формирование отчётов посредством паттерна «Стратегия».

По методичке (лекция №7, слайды 26–28) требуются вложенные замеры, хранение количества вызовов и времени узлов, три стратегии TableReport/TreeReport/JSONReport (Perfetto), проверка работоспособности.

## 2. Модель профилировщика

Класс Node хранит name, parent, children, calls, total. Одинаковые имена, вызванные одним родителем, агрегируются в общий узел. Вызовы из разных ветвей находятся в разных узлах.

В методе Profiler.section(name) текущий узел становится родителем нового вызова. Время измеряется time.perf_counter(). Блок finally фиксирует длительность, добавляет событие временной шкалы и возвращает текущий узел к родителю — также при возникновении исключений.

**Собственное время = max(0, общее время − сумма общего времени дочерних узлов).**

## 3. Паттерн «Стратегия»

Метод Profiler.report(fmt) содержит только вызов fmt.render(self). Таким образом, логика сбора замеров отделена от представления:

| Стратегия | Результат |
| --- | --- |
| TableReport | Плоская таблица с числом вызовов, общим и собственным временем |
| TreeReport | Дерево вызовов с отступами и теми же временными характеристиками |
| JSONReport | Chrome Trace JSON для просмотра в Perfetto |

Новые стратегии можно добавлять без модификации класса Profiler.

## 4. Демонстрация

Сценарий: загрузка уровня около 200 мс; 60 кадров, каждый вызывает update → physics и draw → shadows, sprites. В update исполняется sum(range(30_000)). На 31-м кадре shadows дополнительно задерживается на 20 мс для визуализации пика.

Команда: python main.py.

Фактические показатели демонстрационного запуска:

| Функция | Количество вызовов | Общее время, мс | Собственное время, мс |
| --- | ---: | ---: | ---: |
| загрузка уровня | 1 | 200.1 | 200.1 |
| кадр | 60 | 442.9 | 0.5 |
| update | 60 | 141.0 | 16.0 |
| physics | 60 | 125.0 | 125.0 |
| draw | 60 | 301.4 | 0.9 |
| shadows | 60 | 205.7 | 205.7 |
| sprites | 60 | 94.8 | 94.8 |

Числа измерены при выполнении проекта и могут отличаться при повторном запуске. Наиболее дорогой лист дерева — shadows. Сумма времени верхнеуровневых участков около 643 мс. Плоская сумма всех узлов завышена из-за повторного учёта дочерних замеров.

## 5. Тестирование

Команда: python -m unittest discover -s tests -v. **Пройдены все 13 тестов.**

Проверены: вложенность и собственное время, 60 повторных вызовов, независимые ветви, рекурсия, восстановление после исключения, декоратор, обе текстовые стратегии, JSON с русскими именами, отдельные события, ограничения на длительность и расширяемость через пользовательскую стратегию.

Контрольные условия: собственное время не больше общего; отступы соответствуют иерархии; Profiler не содержит ветвлений по имени стратегии.

## 6. Временная шкала

Экспортируется 361 событие: одно событие загрузки и 60 × 6 событий игрового кадра. Chrome Trace содержит name, ph="X", ts, dur, pid, tid; ts/dur задаются в микросекундах.

На временной шкале соседние кадры имеют около 7 мс, а 31-й — около 27 мс из-за задержки shadows. Такой пик незаметен в дереве суммарных времен, но отчётливо виден по отдельным событиям.

Открытие: https://ui.perfetto.dev → Open trace file → results/trace.json, созданный при выполнении main.py.
